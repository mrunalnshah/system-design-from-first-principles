# T-00.04: Plan checker and trace (TOOL-03)

## Goal
Enabling: make the plan's promises machine-checked (traceability, sizes, round budgets, open conflicts), so drift is caught in CI instead of at review.

## Interface to honour
`check(root): { ok: boolean; problems: string[] }` and `trace(root): string` (writes specs/trace.md). Tooling packets use `feature: tooling`, `module: tooling`; known IDs are REQ criteria, NFR IDs and TOOL criteria.

## Acceptance tests
- TOOL-03.AC1: Given a seeded packet that delivers `REQ-XXX-999.AC1`, when `check` runs, then it fails naming that ID.
- TOOL-03.AC2: Given two packets that depend on each other, when `check` runs, then it fails naming the cycle.
- TOOL-03.AC3: Given a round whose points exceed the budget in rounds.md, when `check` runs, then it fails naming the round.
- TOOL-03.AC4: Given a done task whose criterion has no `@req` test, when `check` runs, then it fails naming the criterion.
- TOOL-03.AC5: Given the real plan as shipped, when `check` runs, then it passes (only `@req` checks for done tasks apply).
- TOOL-03.AC6: Given `trace`, when it runs, then specs/trace.md lists every active criterion with its task.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/check.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Fixing problems the checker finds in the plan: report them to the user as a change request.
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
