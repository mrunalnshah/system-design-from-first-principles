# T-02.02: Book navigation: contents model, previous/next

## Goal
Pure book navigation: contents, previous and next across parts (skipping drafts), first chapter and Roman numerals, plus the `<PrevNext>` component on chapters.

## Interface to honour
`contentsOf`, `neighbours`, `firstChapter`, `romanNumeral` as in specs/contracts/interfaces.md.

## Acceptance tests
- REQ-BOOK-003.AC1: Given the last chapter of Part 1 and the first of Part 2, when the former is built, then "Next" shows the Part 2 chapter.
- REQ-BOOK-003.AC2: Given the first chapter, when it's built, then there's no "Previous" link, and "Contents" stands in its place.
- REQ-BOOK-003.AC3: Given the last chapter, when it's built, then "Next" is replaced by "Back to contents".
- REQ-BOOK-004.AC1: Given `part-2_networks/chapter-5_tcp.md`, when it's shown, then it reads "Chapter 5" in "Part II".
- REQ-CNT-004.AC1: Given Chapter 2 is a draft and Chapters 1 and 3 are not, when Chapter 1 is built, then its "Next" link points to Chapter 3.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- src/features/book/contents.test.ts src/features/book/neighbours.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`
- Compare the result with `design/preview/index.html` (screens: chapter) at phone (375 px) and laptop (1280 px) width, in light and dark

## Done when
- Every acceptance test passes and both reviews pass.
