# T-01.02: Build issues and build report (+ message harness TOOL-15)

## Goal
One place that collects every content problem and prints it the author's way at the end of the build, failing on errors (NFR-013).

## Interface to honour
`buildIssues.add(issue)`, `.all()`, `.hasErrors()`; `buildReport(): AstroIntegration` printing the block format in build-messages.md, errors first, with a non-zero exit on any error.

## Acceptance tests
- REQ-CNT-007.AC2: Given one error and two warnings, when the build runs, then all three are listed together at the end of the log, errors first, and the exit code is non-zero.
- TOOL-15.AC2: Given a code listed in build-messages.md with no fixture, when the harness runs, then it fails naming the code.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- src/features/site/issues.test.ts tests/messages.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Producing the individual messages (each owning task adds its own).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
