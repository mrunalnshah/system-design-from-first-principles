# T-02.04: Keyboard previous/next

## Goal
← and → open the previous and next chapters, never while typing, with a modifier held, or while the diagram viewer is open.

## Interface to honour
Reads `<link rel="prev">`/`<link rel="next">` from the page.

## Acceptance tests
- REQ-BOOK-005.AC1: Given Chapter 1 with a next chapter, when the reader presses →, then the next chapter opens.
- REQ-BOOK-005.AC2: Given the full-screen diagram view is open, when the reader presses →, then nothing navigates.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- src/features/reader/client/keyboard-nav.test.ts`
- `npm --prefix .site run test:e2e -- tests/e2e/keyboard.spec.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`
- Compare the result with `design/preview/index.html` (screens: chapter) at phone (375 px) and laptop (1280 px) width, in light and dark
