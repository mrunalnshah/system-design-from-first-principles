# T-01.23: Styles for math and code

## Goal
Make the renderer's math and code look right in both themes (CR-0006): KaTeX's own stylesheet and fonts served from
the site, and Shiki's `--shiki-light` / `--shiki-dark` colours mapped to the reader's theme, on the code background
token.

## Interface to honour
`.site/src/features/reader/content.css`, imported once by `ReaderLayout.astro` (T-01.16). It imports
`katex/dist/katex.min.css` (bundled with its fonts by the build) and colours `.astro-code` from the Shiki variables
under `prefers-color-scheme`, with no raw colours of its own (TOOL-08).

## Acceptance tests
- REQ-READ-008.AC5: Given a chapter with math, when it's built, then KaTeX's stylesheet and fonts are part of the site's own files, and no page asks another host for them.
- REQ-CNT-005.AC6: Given a highlighted code block, when it's shown in the light and in the dark theme, then its colours follow the theme and its text keeps at least 4.5:1 against the code background (NFR-003).

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tests/content-css.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run tools -- contrast`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- The reader layout itself (T-01.16); display-math overflow (REQ-READ-008.AC3, T-01.16).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
