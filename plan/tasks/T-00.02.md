# T-00.02: Tools entry point and plan tracker (TOOL-02)

## Goal
Enabling: give every later round `status`, `next` and `done`, so agents stop reading state by hand. The plan parser written here is reused by the packer and the checker.

## Interface to honour
`cli.ts <command> [args]` dispatches to commands. `plan.ts` exports `loadPlan(root): Plan` (packets with parsed frontmatter, rounds table, state.json) and the `status`, `next` and `done(taskId)` commands.

## Acceptance tests
- TOOL-02.AC1: Given T-00.01 is done and T-00.02 depends on it, when `next` runs, then T-00.02 is listed under R-01.
- TOOL-02.AC2: Given `done T-00.02`, when it runs, then the packet's status is `done`, progress.md gains one line, and state.json's `build.last_done` is `T-00.02`.
- TOOL-02.AC3: Given an unknown task ID, when `done` runs, then it exits non-zero with "Unknown task".

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/plan.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Packing (TOOL-01) and checking (TOOL-03).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
