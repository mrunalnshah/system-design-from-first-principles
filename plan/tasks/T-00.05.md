# T-00.05: Publish workflow with checks and Pages deploy

## Goal
Careful (security and supply chain): every push to `main` lints, type-checks, tests, builds and, only if all of that passes, deploys to GitHub Pages, with least-privilege permissions and SHA-pinned Actions. The author does the GitHub-side setup in this task: create the public repository `system-design-from-first-principles`, push, set Settings → Pages → Source to GitHub Actions, turn on 2FA and protect `main`. The agent never changes account settings itself.

## Interface to honour
Jobs: `checks` (lint, `astro check`, `vitest run`, `<tools> check`), `build` (needs checks; `astro build`; upload-pages-artifact), `deploy` (needs build; `pages: write`, `id-token: write`; deploy-pages). Default `permissions: contents: read`. Triggers: push to main; pull_request (no deploy). Dependabot: npm weekly in `/.site` and github-actions weekly, each with `cooldown` 7 days (confirm the key in GitHub's docs).

## Acceptance tests
- REQ-SITE-007.AC3: Given only `.obsidian/` changed, when the push runs, then the site still builds and deploys without error.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- The secret scanner (T-00.06), the audit (T-00.10), screen tests (T-01.11).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
