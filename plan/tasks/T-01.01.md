# T-01.01: Token build and contrast check (TOOL-07, TOOL-08)

## Goal
Enabling: generate the site's CSS custom properties from design/tokens.json and guard every colour pair's contrast, before the first styled screen.

## Interface to honour
`buildTokens(json): string` (CSS) and `checkContrast(json): { pairs; ok }`; `<tools> tokens`, `<tools> contrast`; `build` runs tokens first.

## Acceptance tests
- TOOL-07.AC1: Given tokens.json, when `tokens` runs, then tokens.css defines `--color-text` as `#1b2230` on `:root` and `#e6e9ee` inside the dark media query.
- TOOL-07.AC2: Given a token referencing `{color.missing}`, when `tokens` runs, then it exits non-zero naming the token path.
- TOOL-08.AC1: Given the shipped tokens, when `contrast` runs, then every pair passes and the lowest ratio is printed.
- TOOL-08.AC2: Given `text-muted` changed to `#9aa3b0` in light mode, when `contrast` runs, then it fails naming the pair and its ratio.
- TOOL-08.AC3: Given a `#1d5fbf`, `rgb(…)` or `hsl(…)` colour in a component's CSS or an `.astro` style block outside `tokens.css`, when `contrast` runs, then it fails naming the file and line (CR-0003).

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/tokens.test.ts tools/contrast.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Component styles.
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
