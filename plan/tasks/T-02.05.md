# T-02.05: Homepage: book hero (and CNF-006 measurement)

## Goal
The hero (title, subtitle, author, pitch, hero diagram, counts, Read from the start, Contents) with zero JavaScript. Measure the hero LCP with Lighthouse CI and record the result in CNF-006, applying its first option (preload) if over budget.

## Interface to honour
`<HomePage book articles>`, with the hero via `<DiagramFigure file eager>`.

## Acceptance tests
- REQ-HOME-001.AC1: Given `book.md` with title "System Design from First Principles", when the homepage is built, then the hero shows that title as the page's only `h1`.
- REQ-HOME-001.AC2: Given Chapter 1 is the first published chapter, when a reader presses "Read from the start", then Chapter 1 opens.
- REQ-HOME-001.AC3: Given `hero_image: 01-light.svg` and a reader in dark mode, when the homepage loads, then the hero shows `01-dark.svg`.
- REQ-HOME-001.AC4: Given no `hero_image`, when the homepage is built, then the hero shows without an image and the layout doesn't leave a gap.
- REQ-HOME-004.AC1: Given the built homepage, when its requests are listed, then none of them is a script.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test:e2e -- tests/e2e/home.spec.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`
- Compare the result with `design/preview/index.html` (screens: home) at phone (375 px) and laptop (1280 px) width, in light and dark

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Featured and latest sections (T-02.06).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
