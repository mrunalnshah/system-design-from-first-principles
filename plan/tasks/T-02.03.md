# T-02.03: Contents page

## Goal
The contents page: parts with Roman numerals, continuous chapter numbers, and section sub-links, matching the preview.

## Interface to honour
`<Contents book>` rendering `contentsOf(book)`.

## Acceptance tests
- REQ-BOOK-001.AC1: Given Part 1 "Foundations" with Chapter 1, when the contents page is built, then it shows "I. Foundations", then "1. Computer Architecture" with sub-items "Components", "Limitations", "Moore's Law".
- REQ-BOOK-001.AC2: Given a part whose chapters are all drafts, when the contents page is built, then that part isn't shown.
- REQ-BOOK-001.AC3: Given a sub-item, when a reader selects it, then the chapter opens scrolled to that section.
- REQ-ART-003.AC1: Given three articles, when the contents page is built, then none of them is listed.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test:e2e -- tests/e2e/contents.spec.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`
- Compare the result with `design/preview/index.html` (screens: contents) at phone (375 px) and laptop (1280 px) width, in light and dark

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Homepage (T-02.05).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
