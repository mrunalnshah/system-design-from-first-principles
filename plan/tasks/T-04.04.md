# T-04.04: Journey, accessibility, no-JS and responsive suite

## Goal
End-to-end J1–J4 and J6, axe on every screen and state, the full suite with JS off, and the overflow checks from 320 to 1920 px, against the approved preview.

## Interface to honour
Uses the TOOL-09 helpers.

## Acceptance tests
- NFR-003: Accessibility: WCAG 2.2 AA: zero automated violations; every text/background token pair ≥ 4.5:1 (≥ 3:1 for large text and UI borders); full keyboard use; visible focus (measured by: axe checks per screen and state in CI; token contrast check in CI)
- NFR-004: Reading works without JavaScript: All text, diagrams (in the right theme), math, contents and previous/next work with JavaScript turned off; JavaScript only enhances (sticky menu, full-screen diagrams, margin-note taps) (measured by: End-to-end test with JavaScript disabled)
- NFR-010: Diagram quality: Diagrams stay vector-crisp at 200% zoom, fill the reading column (up to 900 px), and never overflow the screen at 320 px width (measured by: Screenshot tests at 320, 768 and 1280 px in light and dark)
- NFR-011: Responsive: No horizontal page scroll from 320 px to 1920 px wide (measured by: Screenshot tests and an overflow assertion in end-to-end tests)

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test:e2e -- tests/e2e/journeys.spec.ts tests/e2e/a11y.spec.ts tests/e2e/nojs.spec.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`
- Compare the result with `design/preview/index.html` (screens: home, chapter, contents, article, articles, about, not-found) at phone (375 px) and laptop (1280 px) width, in light and dark

## Done when
- Every acceptance test passes and both reviews pass.
