# T-02.01: Code map and impact analyzer (TOOL-04, TOOL-05)

## Goal
Enabling: with several modules in place, give agents signatures-only views and change-impact reports.

## Interface to honour
`<tools> map [path] [--budget N]`, `<tools> impact <paths…>`.

## Acceptance tests
- TOOL-04.AC1: Given `.site/src/features/book`, when `map` runs, then it prints `contentsOf`, `neighbours`, `firstChapter`, `romanNumeral` with their signatures and no function bodies.
- TOOL-04.AC2: Given `--budget 500`, when the output would be larger, then it's cut to about 500 tokens with "… (truncated)".
- TOOL-05.AC1: Given `.site/src/features/diagrams/pairs.ts`, when `impact` runs, then it names MOD-diagrams, FEAT-diagrams, REQ-DIAG-001 and the tests tagged with its criteria.
- TOOL-05.AC2: Given paths in two features, when `impact` runs, then it prints a cross-feature warning.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/map.test.ts tools/impact.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Anything else.
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
