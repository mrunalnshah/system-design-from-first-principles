# T-00.09: Boundary rules (TOOL-06)

## Goal
Enabling: enforce module boundaries and dependency direction from the first module on.

## Interface to honour
`npm --prefix .site run lint:boundaries`; rules: outside a module only `index.ts` may be imported; the direction in specs/modules.md; no cycles.

## Acceptance tests
- TOOL-06.AC1: Given a seeded file in `features/home` importing `features/content/scan.ts`, when the check runs, then it fails naming both files.
- TOOL-06.AC2: Given `features/markdown` importing `features/content/index.ts`, when the check runs, then it fails (the markdown module may not depend on the vault module).

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Changing module boundaries.
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
