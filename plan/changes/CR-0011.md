# CR-0011: The vault scan emits W-EMPTY-BOOK, so every build message has a seeded test
Status: approved (2026-11-27, the author chose "emit it" in R-15) · Date: 2026-11-27 · Raised by: phase 3 end check (R-14), T-04.03 (R-15)

## Why
`specs/contracts/build-messages.md` lists W-EMPTY-BOOK ("no published chapters", fix "Publish a chapter by removing
draft: true."), and `design/screens/contents.md` promises a build warning with the contents page's empty state. But
no task ever built it: since R-06 the build emits it nowhere, and the TOOL-15 harness skips it as `UNOWNED`. T-04.03
must close NFR-013 ("every code in build-messages.md has a broken-vault fixture"), which it can't while the code
is never produced. The emitting code is MOD-vault's (`.site/src/features/content/scan.ts`), outside T-04.03's files.

## What
MODIFIED `plan/tasks/T-04.03.md` (ready, R-15):
- files: **ADDED** `.site/src/features/content/scan.ts` (3 files, within size S).
- Done when: **ADDED** "W-EMPTY-BOOK is emitted by the vault scan and has its fixture; `UNOWNED` in
  `.site/tests/messages.test.ts` is empty (CR-0011)."
- Points unchanged (S/2).

The rule, in `scanVault` (MOD-vault, no interface change): when the vault has no published chapter, warn W-EMPTY-BOOK,
unless a chapter file already has a frontmatter issue (that error already stops the publish and is the one message
to act on; the warning shows once it's fixed, if every chapter is still a draft). It names the first draft chapter and the line of its `draft:` field, where the fix is
made; with no chapter file at all, it names `book.md`. A warning: the site still builds, with the contents page's
empty state ("The first chapter is on its way.").

Fixtures (T-04.03's own files): **ADDED** `tests/fixtures/broken/W-EMPTY-BOOK/`; a published chapter added to the
fixtures that had none (E-FRONTMATTER-FIELD, W-ABOUT-MISSING, W-ARTICLE-UNDATED), so each still produces exactly its
own message.

No spec text changes: build-messages.md and contents.md already describe this behaviour.
