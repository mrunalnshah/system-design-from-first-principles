# T-01.06: Obsidian Markdown core renderer

## Goal
The deep, general-purpose `renderObsidian()`: CommonMark + GFM + wikilinks, comments, highlights, callouts and build-time Shiki, so vault files render as they do in Obsidian (NFR-009).

## Interface to honour
`renderObsidian(source, ctx): Promise<RenderResult>` exactly as in specs/contracts/interfaces.md; W-LINK-UNRESOLVED and W-SYNTAX-UNKNOWN issues with original line numbers.

## Acceptance tests
- REQ-CNT-005.AC2: Given `[[chapter-1_computer-architecture|Chapter 1]]` in an article, when it's rendered, then it's a link to Chapter 1's page with the text "Chapter 1".
- REQ-CNT-005.AC3: Given `%%private note%%`, when it's rendered, then the text doesn't appear in the HTML.
- REQ-CNT-005.AC4: Given a fenced `python` code block, when it's rendered, then it's highlighted at build time, with no JavaScript needed.
- REQ-CNT-005.AC5: Given Obsidian's tab-indented nested lists (as in Chapter 1), when they're rendered, then the nesting matches Obsidian's reading view.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- src/features/markdown/render.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`
- Compare the result with `design/preview/index.html` (screens: chapter, article) at phone (375 px) and laptop (1280 px) width, in light and dark

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Embeds (T-01.07), math (T-01.08), headings (T-01.09), footnotes (T-01.10).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
