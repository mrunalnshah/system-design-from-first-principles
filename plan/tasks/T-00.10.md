# T-00.10: Dependency audit, cooldown and licence check (TOOL-14)

## Goal
Enabling: enforce the 7-day cooldown, known-vulnerability and licence rules on every change, plus a weekly scheduled run.

## Interface to honour
`audit(): { ok; problems }`, using `npm audit --json`, registry `time` data for each lockfile entry and `npm sbom --sbom-format cyclonedx`.

## Acceptance tests
- TOOL-14.AC1: Given a lockfile entry published 2 days before the change, when `audit` runs, then it fails naming the package.
- TOOL-14.AC2: Given a dependency with licence GPL-3.0, when `audit` runs, then it fails naming the package.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/audit.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Upgrading dependencies.
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
