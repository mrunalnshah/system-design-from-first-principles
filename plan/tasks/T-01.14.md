# T-01.14: Vault loader wired in; Chapter 1 live

## Goal
The custom loader (main path or S-01's fallback) renders every entry through `renderObsidian()`, and Chapter 1 goes live with both diagrams correct in light and dark. Its golden test uses the real Chapter 1 read-only.

## Interface to honour
`vaultLoader({ vaultRoot })`, `getBook()`, `getArticles()`, `getPage()` as in specs/contracts/interfaces.md; route `/book/[slug]/` with `getStaticPaths` from `getBook()`. Render every published entry during content sync, with `createFigureRenderer(await getDiagramIndex(vaultRoot()))`, so `diagramAssetPaths` sees every referenced diagram before pages are built; use `vaultRoot()` from MOD-site (CR-0007).

## Acceptance tests
- REQ-BOOK-002.AC1: Given `chapter-1_computer-architecture.md`, when it's published, then its address is `/book/computer-architecture/`.
- REQ-BOOK-002.AC3: Given a chapter is renumbered from 1 to 2, when the site is rebuilt, then its address doesn't change.
- REQ-DIAG-001.AC2: Given a reader in dark mode, when the figure loads, then `01-dark.svg` is shown and `01-light.svg` isn't downloaded.
- REQ-DIAG-001.AC5: Given JavaScript is off, when the reader's system switches theme, then the figure switches too.
- REQ-DIAG-002.AC3: Given a 320 px screen, when any diagram is shown, then it fits the screen width with no horizontal page scroll.
- REQ-DIAG-005.AC1: Given Chapter 1 on a slow connection, when its diagrams load, then the page's layout shift (CLS) stays ≤ 0.1.
- REQ-SITE-007.AC1: Given a push with a new chapter, when the run finishes, then the chapter is live within 10 minutes (NFR-005).
- NFR-009: Source fidelity: Every published vault file renders without edits to it: Obsidian embeds, light/dark SVG pairs, `$…$` and `$$…$$` math, footnotes, callouts, tables, code blocks (measured by: Golden tests on fixture files, plus Chapter 1 rendered as an end-to-end fixture)

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.
