# CR-0013: Guard tests for the measured NFRs (publish time, cost, no server)
Status: approved (2026-11-27, the author chose "add guard tests" in R-15) · Date: 2026-11-27 · Raised by: T-04.05's review (R-15)

## Why
NFR-005 (publish time), NFR-007 (cost) and NFR-012 (no server of our own) are measured, not coded: by the deploy
job's timestamps, by the plan GitHub gives a public repository, and by the author's monthly look at the site.
T-04.05 records those measurements in `specs/operations.md#release-readiness-results-t-0405-2026-11-27`. But
`tools check` (`.site/tools/check.ts`) requires every criterion of a done task to have a test tagged `@req`, and
T-04.05's packet lists no test file, so marking it done would fail the phase's definition of done ("check clean").

## What
MODIFIED `plan/tasks/T-04.05.md` (ready, R-15), Done when: **ADDED** "NFR-005, NFR-007 and NFR-012 each have a guard
test tagged `@req` in `.site/tests/workflow.test.ts` (CR-0013)." Its files list stays as it is (size S allows 3):
like CR-0010 and CR-0011, the test file is logged wiring outside the packet. Points unchanged.

The guards pin what keeps each measurement true, and that the measurement is recorded:
- NFR-005: a push goes live by itself: `deploy` needs only `build`, with no approval step and no queue behind other
  runs' deploys being cancelled; and operations.md records a measured 95th percentile of at most 10 minutes.
- NFR-007: the workflow uses no secret and no paid runner (only GitHub's standard `ubuntu-` runners), and calls
  only GitHub's own Actions; operations.md records the cost check.
- NFR-012: the site is built as static files (`output: "static"`, no server adapter) and published only as the Pages
  artifact of `.site/dist`; operations.md keeps the monthly site check, with at least one dated line.

## Impact
`<tools> impact .site/tests/workflow.test.ts`: tests only; no code, spec or round change. The measurements stay the
evidence; the guards keep a later change from silently undoing them.
