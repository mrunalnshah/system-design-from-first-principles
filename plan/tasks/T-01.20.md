# T-01.20: Lighthouse budgets, size check, link check (TOOL-10..12)

## Goal
Enabling: put NFR-001, NFR-002 and REQ-SITE-013 under automatic guard in CI before the homepage arrives.

## Interface to honour
`<tools> size`, `<tools> links`, `npm --prefix .site run test:lighthouse`; all three run in the `build` job.

## Acceptance tests
- TOOL-10.AC1: Given the budgets file, when the run finishes, then the report lists LCP and CLS for each page and fails the job if a budget is exceeded.
- TOOL-11.AC1: Given a page referencing 70 KB of compressed JS, when `size` runs, then it fails naming the page and the number.
- TOOL-11.AC2: Given the homepage, when `size` runs, then it reports 0 KB of JS.
- TOOL-12.AC1: Given a built page with `href="/book/x/"` (no base path), when `links` runs, then it fails naming the page.
- TOOL-12.AC2: Given the full site, when `links` runs, then every internal link resolves.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/size.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Tuning pages to pass (owning tasks).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
