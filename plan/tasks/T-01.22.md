# T-01.22: Sync: one command to collect diagrams, check, build, commit and push

## Goal
Careful (it commits and pushes on the author's behalf): the author's whole publish step becomes one double-click (CR-0005). In order: pull (fast-forward only); move Excalidraw's `excalidraw/<name>.excalidraw.light.svg`/`.dark.svg` into the part's `diagram/` as `<name>-light.svg`/`-dark.svg`; refuse missing, one-sided or stale images (older than the drawing); build the site; show what changed; ask for a one-line message; commit (the pre-commit hook still runs gitleaks and the boundary check); push; print the Actions link and the site address. It stops before committing at the first problem, and it never edits chapter text.

## Interface to honour
`sync(opts: { root; ask(question): string; log(line): void; now?: Date; run?: (cmd, args) => { status, stdout, stderr } }): { ok: boolean; committed?: string }` in `.site/tools/sync.ts`, with `collectDiagramImages(root)` and `staleDrawings(root)` exported for tests. CLI: `npm --prefix .site run sync` → `tools -- sync`. `sync.cmd` at the vault root runs `npm --prefix "%~dp0.site" run sync` and pauses, so a double-click window stays open. Tests use a temporary git repository with a local bare repository as `origin`, never GitHub.

As built (recorded after review, 2026-11-26): `ask` returns a `Promise<string>` (readline is asynchronous), and the injectable `build?: () => RunResult` replaces `run?`, because the build is the only step tests need to fake; git always runs for real against the temporary repositories. `collectDiagramImages` returns `{ moved, problems }`, so a locked file becomes a plain message instead of a crash.

## Acceptance tests
- REQ-AUTH-001.AC1: Given a new chapter and its drawing's exported images, when sync runs and the author enters "Add chapter 2", then one commit with that message holds the chapter and its `diagram/` images, and it's pushed to `origin main`.
- REQ-AUTH-001.AC2: Given a drawing saved after its images were exported, when sync runs, then it stops before committing and names the drawing with "open it in Obsidian and save it (Ctrl+S)".
- REQ-AUTH-001.AC3: Given a site build that fails, when sync runs, then it stops before committing and shows the build's report.
- REQ-AUTH-001.AC4: Given nothing changed since the last sync, when sync runs, then it says "Nothing new to publish" and makes no commit.
- REQ-AUTH-001.AC5: Given new commits on GitHub (for example a merged Dependabot update), when sync runs, then it pulls them first; if a fast-forward isn't possible it stops and explains what to do.
- REQ-AUTH-001.AC6: Given the push succeeded, when sync ends, then it prints the link to the GitHub Actions run list and the site's address.
- REQ-AUTH-002.AC1: Given `part-1_foundations/excalidraw/01_computer-architecture.excalidraw.light.svg` and `.dark.svg`, when sync runs, then `part-1_foundations/diagram/01_computer-architecture-light.svg` and `-dark.svg` hold their contents and the originals are gone.
- REQ-AUTH-002.AC2: Given a drawing with a light export but no dark one, when sync runs, then it stops, naming the drawing and the missing dark image.
- REQ-AUTH-002.AC3: Given a drawing with no exports and no images in `diagram/`, when sync runs, then it stops with "open it in Obsidian and save it (Ctrl+S)".

## Out of scope
- Rendering SVGs without Obsidian (rejected in ADR-0012; Obsidian's auto-export makes them).
- Rewriting chapter files (drawing embeds are swapped at build time, REQ-DIAG-007).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/` text, `articles/`, `.obsidian/`); moving the exported images is the only change sync makes in the vault.
