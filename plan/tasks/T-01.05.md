# T-01.05: Summaries and reading time

## Goal
Give every card and meta description a summary and every entry a reading time, with no author effort.

## Interface to honour
`summaryOf(markdown, description?): string` (≤ 200 chars at a word boundary, with "…"); `readingMinutes(markdown): number` (ceil(words / 230), min 1).

## Acceptance tests
- REQ-CNT-008.AC1: Given Chapter 1 without `description`, when its card is built, then the summary starts "Before we can learn how to design large-scale distributed system".
- REQ-CNT-008.AC2: Given a first paragraph of 500 characters, when the summary is built, then it's at most 200 characters, ends at a word boundary and ends with "…".
- REQ-CNT-009.AC1: Given a 700-word chapter, when it's built, then it shows "4 min read".

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- src/features/content/summary.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Cards that show them (phase 2).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
