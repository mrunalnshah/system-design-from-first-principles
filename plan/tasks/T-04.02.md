# T-04.02: Performance and build-time budgets (TOOL-16)

## Goal
Measure NFR-001, NFR-002 and NFR-006 at realistic size: a generated 60-chapter/100-article vault builds in 2 minutes or less, and every page meets its Lighthouse and size budgets.

## Interface to honour
`<tools> gen-vault <dir> --chapters N --articles M`.

## Acceptance tests
- TOOL-16.AC1: Given `--chapters 60 --articles 100`, when it runs, then the folder builds without errors and contains 60 chapters and 100 articles.
- NFR-001: Loading speed: Largest Contentful Paint ≤ 2.5 s and CLS ≤ 0.1 on a mid-range phone over a 4G connection, for the home, contents and chapter pages (measured by: Lighthouse CI (mobile preset) in CI on every push; fails the build when exceeded)
- NFR-002: Page weight: ≤ 60 KB of compressed JavaScript per page; a chapter page's HTML+CSS+fonts ≤ 250 KB compressed, excluding diagrams; only the diagram variant matching the theme is downloaded (measured by: Build-size check in CI; network trace in an end-to-end test)
- NFR-006: Build time: Full build ≤ 2 minutes for 60 chapters and 100 articles (measured by: Timed build against generated fixture content in CI)

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/gen-vault.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run lint:boundaries`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Feature changes. File a change request if a budget can't be met.
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
