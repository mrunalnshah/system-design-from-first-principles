# T-01.21: Writing guide and templates

## Goal
Give the author everything needed to write well with this system, in Obsidian (CR-0005). WRITING-GUIDE.md covers: the folder layout (parts, chapters, `excalidraw/`, `diagram/`), naming rules, every frontmatter key with an example, headings and their numbers, footnotes as margin notes, callouts, math (and KaTeX's limits, e.g. `\mu` not `\micro`), code, tables, links between chapters, drawings and captions, drafts, featured chapters and articles, `book.md`, `about.md`, renaming with `moved_from`, publishing with sync, and what every build or sync message means. Each feature is marked as live on the site now or coming in a named round. Templates give ready-to-copy frontmatter and structure.

## Interface to honour
Plain Markdown an Obsidian user reads in Obsidian. The templates work with Obsidian's core Templates plugin (the guide says how to point it at `templates/`). `.site/tests/guide.test.ts` keeps the guide in step with the contracts.

## Acceptance tests
- REQ-AUTH-003.AC1: Given `specs/contracts/frontmatter.schema.json`, when the guide is checked, then every key in it is explained in the guide and appears in at least one template.
- REQ-AUTH-003.AC2: Given `specs/contracts/build-messages.md`, when the guide is checked, then every message code is explained in its "When sync or the build stops" section.
- REQ-AUTH-003.AC3: Given the `templates/` folder, when the content rules decide what to publish (REQ-CNT-003), then nothing in it is published: it's outside `part-*/` and `articles/`.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tests/guide.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`
- `npm --prefix .site run tools -- check`

## Done when
- Every acceptance test passes and both reviews pass.

## Out of scope
- Writing book.md or about.md themselves: those are the author's (the templates show the shape).
- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
