# CR-0006: Styles for math and code, and what R-07's renderer settled
Status: approved (2026-11-26, option A) · Date: 2026-11-26 · Raised by: the R-07 review

## Why
R-07 built the Markdown renderer (T-01.06 to T-01.09). Its review found four things the plan doesn't cover yet:
1. **Math and code need styles that no task ships.** KaTeX's HTML only looks right with KaTeX's stylesheet and
   fonts (ADR-0008, Consequences), and without them each formula shows twice: as unstyled text and as MathML.
   Shiki writes code colours as CSS variables (`--shiki-light`, `--shiki-dark`) so the theme can choose, and
   without a rule mapping them, code has no colours. T-01.16 (reader layout) doesn't mention either.
2. **Two helpers the vault loader needs are exported but not in the interface contract:**
   `createFileResolver(paths)` (Obsidian's lookup for `![[name]]`) and `slugify(text)` (the anchor rule).
3. **Headings inside a callout, quote or list:** the renderer treats only the document's own top-level headings
   as sections (numbered, and in the chapter menu). REQ-READ-004 doesn't say.
4. **A `%%` comment that's never closed** hides the rest of the entry, as in Obsidian. The renderer now warns
   (W-COMMENT-UNCLOSED). standards.md lets a task add a code with its seeded test; it's listed here for the record.
