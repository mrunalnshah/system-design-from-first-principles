# CR-0007: What R-08's figures and notes need from the tasks after them
Status: approved (2026-11-27, option A) · Date: 2026-11-26 · Raised by: the R-08 review

## Why
R-08 built margin-note markup, the diagram index and figures, and the screen-test harness. Its review settled
three things later tasks must now do, which their packets don't say yet. Without them the work is lost or wrong.
1. **Only diagrams that a published entry shows are put on the site** (interfaces.md, "every referenced diagram
   asset"; drafts stay unpublished, REQ-CNT-004). The figure renderer records each diagram it draws, and the
   diagram route publishes only those. So the vault loader must render every entry during content sync, before
   pages are built, and the homepage hero must be drawn through MOD-diagrams too.
2. **The vault root is fixed in one place:** `vaultRoot()` in MOD-site, set by astro.config.ts from its own location
   (it was `process.cwd()` in two files). The loader should use it.
3. **Three page-level checks** belong to the reader tasks:
   - REQ-READ-008.AC5 was proven by construction (every KaTeX font is a local file the build bundles). The built
     chapter page should be checked too: no request to another host (TOOL-09 `expectOnlySameOriginRequests`).
   - figure.css caps a wide figure by `--figure-room` (default: the screen minus gutters). With the 15 rem chapter
     menu at 1100 px and wider, the reader layout must set it, so a 900 px figure never overlaps the menu.
   - REQ-READ-006.AC3 (notes listed at the end, JavaScript off, on a phone) also needs the inline `.sidenote` hidden
     on narrow screens without JavaScript.
