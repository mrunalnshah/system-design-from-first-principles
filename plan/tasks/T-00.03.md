# T-00.03: Context packer (TOOL-01)

## Goal
Enabling: one command that bundles exactly what a task or round needs, so every later round loads less context.

## Interface to honour
`pack(target: string, opts: { out?: string }): { text: string; tokens: number; warnings: string[] }`, where target is a task ID or round ID. Heading anchors are matched by GitHub-style slugs.

## Acceptance tests
- TOOL-01.AC1: Given a packet that delivers REQ-CNT-001.AC1, when `pack` runs, then the bundle holds the REQ-CNT-001 section and the MOD-vault module entry.
- TOOL-01.AC2: Given a bundle larger than the packet's budget, when `pack` runs, then it prints a warning with both numbers.
- TOOL-01.AC3: Given `load: [specs/standards.md#testing]`, when `pack` runs, then only that heading's section is included, not the whole file.
- TOOL-01.AC4: Given a round ID, when `pack R-05 --out R-05-pack.md` runs, then one file holds every packet of R-05 in order.

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.

## Verify
- `npm --prefix .site run test -- tools/pack.test.ts`
- `npm --prefix .site run lint` and `npm --prefix .site run check`

## Done when
- Every acceptance test passes and both reviews pass.

- Editing the author's vault files (`book.md`, `about.md`, `part-*/`, `articles/`, `.obsidian/`).
