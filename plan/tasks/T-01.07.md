# T-01.07: Embeds resolved like Obsidian

## Goal
`![[name]]` finds the file the way Obsidian does (closest match first), hands SVG embeds (grouping consecutive light/dark ones) to the figure renderer, and refuses drawing-source embeds.

## Interface to honour
`resolveFile(name, fromPath)` with Obsidian's shortest-path rule; the embed plugin calls `ctx.figure({ files, alias, fromPath, line })`; E-EMBED-MISSING and E-EMBED-DRAWING.

## Acceptance tests
- REQ-CNT-006.AC1: Given `![[01-light.svg]]` in `part-1_foundations/chapter-1_…md` and the file at `part-1_foundations/diagram/01-light.svg`, when it's rendered, then the diagram appears.
- REQ-CNT-006.AC2: Given `![[missing.svg]]`, when the build runs, then it stops with a build error naming the entry, the line and the missing file name.
- REQ-CNT-006.AC3: Given two files named `01-light.svg` in different folders, when one is embedded from a chapter, then the one in the chapter's own part folder is used.
- REQ-DIAG-006.AC2: Given a chapter that embeds `![[01_computer-architecture.excalidraw]]`, when the build runs, then it stops with E-EMBED-DRAWING: "Embed the exported SVG instead, e.g. ![[01_computer-architecture.excalidraw.light.svg]]."

## Steps
1. Write the interface comment and signatures.
2. Write one failing test per criterion, each tagged `@req <criterion-id>`.
3. Implement until the tests pass.
4. Run Verify and log the output.
